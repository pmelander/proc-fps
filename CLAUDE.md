# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Null Sector (working name and repository: proc-fps) is a fully procedural, Doom-style browser FPS: 2.5D sector geometry rendered in true 3D by a custom WebGL2 renderer, driven by a deterministic 60 Hz sim. Movement is grid-based (one 128-unit cell per step) with free mouse look. `PROJECT_SUMMARY.md` holds the design rationale, known gaps, roadmap and open questions. Read it before architectural work.

## Commands

TypeScript 7, Vite 8, Vitest 5, tsx, npm workspaces. CI uses Node 22.

```bash
npm install
npm run dev                          # Vite app → http://localhost:5173/ (new run)  or  ?run=id&level=n, ?seed=anything[&type=compound|ascent|descent], ?map=test01 … test07 (test07: the charger, bloater and warden, and the M25 pickups)  (&autoplay runs without pointer lock);  /browse.html = seed browser
npm run typecheck                    # tsc --noEmit over every package
npm test                             # vitest run (packages/*/test/**/*.test.ts, Node env)
npx vitest run packages/sim/test/sim.test.ts          # one file
npx vitest run -t "buffers a press made mid-step"     # one test by name
npm run maps:build                   # regenerate packages/core/maps/*.json from build-test-maps.ts
npm run gen:stats -- --seeds 2000    # generator health check (any invalid map exits non-zero) + level distributions
npm run ci                           # typecheck + test + gen:stats (2000) + build
```

In addition to `npm run ci`, the CI pipeline (`.github/workflows/ci.yml`) runs `maps:build` and then `git diff --exit-code packages/core/maps`. After any change to `MapBuilder`, the map format, or `build-test-maps.ts`, run `npm run maps:build` and include the regenerated JSON. Never hand-edit `maps/*.json`.

## Architecture

Packages are source-first: each `package.json` `exports` points straight at `src/index.ts`, so there is no build step between packages. Relative imports use `.js` extensions, and type-only imports need `import type` (`verbatimModuleSyntax`). `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` are on.

Data flows one way. **`MapData` (core/map.ts) is the contract** between producers and consumers:

```
gen.generate(seed) ─┐                       ┌─> sim: createWorld(map) → stepSim(world, state, InputFrame) per tick
core MapBuilder ────┴─> MapData ─ validate ─┤
(test maps)                                 └─> render: buildLevelMesh(map) → LevelRenderer → RenderBackend (WebGL2)
```

- **core**: map format v1 (sectors may carry a `slab`: a catwalk, giving their cells two walkable levels) and `hashMap`, `CellPlan`/`emitCellPlan` (cells → sectors; outlines split automatically wherever the neighbour changes, so generators never place T-junction vertices by hand; throws on pinch points), `Rng` (sfc32 with named forks), deterministic trig (`dsin`/`dcos`), `MapBuilder` + `rect`, sector loop geometry and `SectorLocator`, and `CellGrid`. `CellGrid` is derived from the sector map and is the single movement truth, level-aware (`stepTarget(cx, cy, level, h)` returns the landing level; `reachStates` searches (cell, level) states): `canStep` is shared by the sim, the generator validation, and future AI.
- **gen**: `generate.ts` runs mission → layout → room templates → `CellPlan` → sectors (`GENERATOR_VERSION = '0.23.0'`, `generate(seed, { level, type })`); `generateDetailed` also returns the mission, layout, room designs, attempt count and failure reasons. `mission.ts` is the mission graph (rooms and door types, built as Dormans-style cycles; `validateMission` checks the key and mini-boss progression). Level types (`levels.ts`: compound, ascent, descent; a run paces them with `levelTypeFor(level)`) set the mission size, room sizes and storeys. `assignStoreys` maps each room's `progress` along the critical path to one of up to 6 storeys (key and secret connections never cross storeys). A corridor between storeys ends in a lift, or runs at the upper floor as a bridge (a catwalk into the lower room ending in a lift), a one-way drop (a ledge high in the lower room's wall, kept only if `strandsPlayer` in `progress.ts` says no state can strand the player), or onto an atrium's catwalk ring (`atriumDesign`). `population.ts` places enemies, health and ammo, balanced by the run level and each room's mission-graph depth (for a given seed and type the level changes only the population, never the layout). `rooms.ts` holds the room templates (each keeps the room's outer ring as base floor, so doorways stay connected). `layout.ts` embeds the mission on the grid: rooms placed along a spanning tree with straight corridors, loops routed by turn-penalised pathfinding, and a separation rule so structures touch only at doorways. Floors are flat within each storey. Failed layouts retry on the next deterministic RNG fork. `validateGenerated` layers gameplay checks (grid alignment, reachability, traps, key progression, and `validateProgress`: a search over (cell, level, keys held) states so drops can never strand the player) on top of core's structural `validateMap`. `gen:stats` cycles through the level types.
- **sim**: fixed-step state machine. `InputFrame`s go in; `SimState` holds the player, door progress (per door id, doors stay open), held keys, taken pickups, found secrets, and per-tick `events`. Enemy stats come from `world.enemyDefs` via `defOf(defs, enemy)`: `enemyDefsFor(map.meta.seed)` (core/bestiary.ts) breeds seeded stats per generated level within the tuning rules, two variants per ordinary role (`EnemyState.variant`, from the `THING_VARIANT` flag the generator sets); maps without a seed use the baseline (`BASELINE_DEFS`). `World` derives doors (`doorSectors` order = door id) and key pickups from the map. Movement asks a `MoveGate` (`tryStep`: go / wait / no) that covers doors (walking into an auto door opens it; key doors open with use while holding the key; secret doors open with use and count as found), lifts (`lifts.ts`: called when not level, ride after `LIFT_WAIT`; `floorNow` is the real floor height), and enemies in the way. Hazard floors (`SPECIAL_DAMAGE`) hurt on a timer; other hurts carry `from`, the hit's source, for the HUD's direction glow. Combat: `ENEMY_DEFS`, the guns (`WEAPONS` in core/src/weapons.ts: the scattergun, the heavy bolter, whose bolts burst as `blast` events, and the railgun, whose slugs pierce every enemy to the wall (`pierce`); ammo is infinite but each gun's magazine, `PlayerState.mags`, empties into a reload, or early on the `reload` input; the `weapon` input switches guns over `WEAPON_SWITCH_TICKS`; the `grenade` input lobs one of the scarce `GRENADE`s, which arc and burst in `stepGrenades`), run perks (`core/src/perks.ts`: `createWorld(map, perks)` folds them into `world.mods`, which the sim reads for health, magazines, reloads, damage and the like; replays record them), armour and the berserk and overcharge power-ups (`core/src/powerups.ts`: `hurtPlayer` lets armour soak its share, `playerFire` applies the boosts), the chainsword (`MELEE_*`: firing at an enemy in reach, or the `melee` input, starts a grinding attack with invulnerability frames; `hurtPlayer` turns hits away as `shielded`), melee and health constants live in core (`core/src/enemies.ts`, `constants.ts`) because the generator balances against them; sim re-exports them. `ai.ts` (state machine, distance-field pathing, sight and noise wake-up; enemies ride lifts by the player's rules, some flank via a second field towards a point beside the player, and `THING_HIGH` enemies start up on a catwalk; chargers rush down straight lanes (`rush`), bloaters burst (combat.ts `detonate`, chain reactions included), and a warden's shield stops direct shots from its front (`shieldStops`); `boss.ts` gives the mini boss and boss phases and rotating attacks: volleys, ring bursts, walls, split shots, spirals, homing fans, summons, slams, all unblockable; `shots.ts` holds the projectile patterns: lobs, homing orbs, walls, splits and spiral emitters, which grunt variants use via `EnemyDef.shot`), `combat.ts` (player hitscan, damage, projectiles), `raycast.ts` (grid DDA for line of sight and `castRay` against cells, floors, ceilings and doors). Enemies and projectiles live in `SimState`; `dead`/`won` freeze the level. `ReplayRecorder` and `runReplay` store a map hash plus the input log, and `hashState` pins behaviour in tests.
- **render**: `RenderBackend` interface with the WebGL2 implementation behind it. The mesh is static and grouped per sector (`LevelRenderer.sectorRanges`); portal culling (`visibility.ts`, `PortalGraph`) draws only the sectors the camera can see, their ranges merged into one call (`DrawCall.ranges`). Moving parts are *movers*: vertices tagged with a mover id (door ids, then key pickups) shift down by `LevelRenderer.movers[id]`, a uniform array the app fills each frame from sim state (door slabs lower, taken pickups sink out of view). Enemies, corpses and projectiles are a separate dynamic sprite pass (`sprites.ts`, `buildSpriteVertices` + `RenderBackend.updateVertexBuffer`), sampled from a sprite atlas baked per level from SDF models (`SPRITE_BAKE_FS`, 5 shapes × 8 directions × 4 frames; `spriteTile`) bred by `enemyLooks(seed, theme)` (`bestiary.ts`: 8 rows, the ordinary roles twice for their two variants, see `spriteRow`; body plans with four leg types, glowing markings, and skins whose hues avoid the theme's colours), projectiles drawn procedurally. Level textures are baked per level into an atlas (`ATLAS_FS`) in the colours of the map's theme (`themes.ts`, `meta.theme`), and `LEVEL_FS` samples it with `texelFetch`. The scene renders at low resolution, then a 64-colour palette post pass applies Bayer dithering, also at low resolution (each theme has its own palette, `palette.ts`, built from its colours with fixed ramps for blood, bone and the key colours; the UI and automap use it too): the app sizes the canvas to the scene (`renderer.lowResHeight` rows) and CSS scales it up pixelated. F3 shows a perf overlay (F4 toggles culling).
- **app**: browser shell only. It holds the loop with tick interpolation (the sim steps only while the pointer is locked), DOM input → `InputFrame`, the HUD compass, the door prompt (E, or the missing key, above the crosshair), held keys (icons above the health), and the automap (hold Tab; look direction up; `automap.ts` samples the grid cell under each low-res pixel, so floors fill and walls outline the open level). `weapon.ts` is the energy scattergun view model (drawn over the barrel from above; coils glow in the theme colour) and `gore.ts` the gib and blood particles (both render-only, never in the sim or replays). `src/audio/` holds the jsfxr-style synth, the seeded sound set, the music generator and the WebAudio engine (unlocked on the start click; events → sounds). `sprites.html` shows the baked sprite sheet (`?seed=&theme=` for a level's mutants and their stats). `browse.html` + `src/browse.ts` is the seed browser (a second Vite entry, `vite.config.ts`), drawing `src/thumbnail.ts` top-down maps with `levelStats` from gen. F8 downloads the current replay. The UI (`src/ui/`): `font.ts` builds the procedural pixel font into TrueType bytes at load, `skin.ts` registers it and sets the UI pixel `--u`, the palette-drawn textures and the theme accent that `style.css` uses, `menu.ts` is the keyboard/mouse menu every screen uses, `tally.ts` the end-of-level count-up, `optionspanel.ts` the options panel over `options.ts` (the player's settings in browser storage; render- and input-side only). A fresh load shows the title screen (`title.ts`); runs (`run.ts`, browser storage) track each cleared level's score across page loads, and `screens.ts` builds the end-of-level and run-summary screens. Difficulty (`core/src/difficulty.ts`) is a run setting in the URL: the generator scales enemies and health, the sim enemy damage.

## Invariants

1. `core`, `gen` and `sim` never import DOM APIs. They run in Node for tests and CI, and later in a Worker. Only `render/webgl2.ts` and `app` touch the DOM.
2. No `Math.random` in core, gen or sim. Use `Rng` and fork a named stream per subsystem, so that one subsystem's draws never reshuffle another's. (`app` uses `Math.random` only to pick a URL seed.)
3. No `Math.sin/cos/atan2/hypot/pow` in sim. They differ at the ULP level across JS engines and break replays. Use `dsin`/`dcos`. `+ - * / sqrt floor round` are safe.
4. The sim advances only through `stepSim`, at 60 Hz. Rendering interpolates between the previous tick and the current one.
5. Bump `GENERATOR_VERSION` for any change that alters output for an existing seed. Bump `MAP_FORMAT_VERSION` for breaking format changes.
6. A changed replay or state hash in a test is a behaviour change. Decide deliberately. Don't just update the expected value.
7. `CELL_SIZE`, `STEP_TICKS`, enemy step timers and projectile speeds are tuned together.

## Geometry conventions

- In map space, (x, y) has y pointing north. World space is X = x, Y = up, Z = −y. Heading 0/1/2/3 = E/N/W/S = h × 90°.
- A linedef's front side is on the **left** of v1→v2 (Doom uses the right). Outer sector loops are CCW, holes are CW.
- All geometry is axis-aligned on the 128 lattice, and things sit at cell centres (`validateGridAlignment`).
- Adjacent sectors must share identical edges. Split T-junctions with `rect(..., { east: [...] })`. Loops that touch at a single vertex are unsupported (`chainLoops`).
- `MapBuilder` merges shared edges into two-sided lines. A wall takes its texture from the side it is seen from, so a platform riser needs `setSideTextures` to override the surrounding room's `lower` texture.
- Units: cell 128, player height 72, eye 64, max step 24. Taller than Doom's 56/41, which only read right through Doom's 1.2 vertical pixel stretch. Openings must be at least `PLAYER_HEIGHT` tall.
